## Guard Checks

### 1. Caddy Drift

Detect:

- production-only routes not represented by the Caddy template or route docs
- missing expected routes
- upstream port changes
- static root changes
- `/workspace/JOB-*` route missing or changed
- `/downloads` or `/downloads/` behavior missing
- `/real` redirect missing
- generated status/proof route changes

Planned command shape:

```bash
ssh root@farpy.com 'caddy adapt --config /etc/caddy/caddy.real.json --pretty'
ssh root@farpy.com 'sha256sum /etc/caddy/caddy.real.json /etc/caddy/Caddyfile 2>/dev/null || true'
```

Output:

- normalized production route summary
- diff against source-controlled route families
- fail on missing P0 routes
- warn on extra routes until classified

### 2. systemd Drift

Detect:

- launch-critical services missing
- launch-critical services disabled unexpectedly
- unexpected inline secret-bearing `Environment=` values
- missing required `EnvironmentFile=` drop-ins
- changed `ExecStart` paths for critical services
- timers disabled unexpectedly
- Caddy drop-ins missing

Planned command shape:

```bash
ssh root@farpy.com "systemctl list-unit-files 'farpy*' 'caddy*' --no-pager --no-legend"
ssh root@farpy.com "systemctl cat caddy farpy-auth farpy-checkout-api farpy-upload-api farpy-jobs-api farpy-web-render-api --no-pager"
ssh root@farpy.com "systemctl list-timers 'farpy-*' --no-pager"
```

Output:

- service status matrix
- unit file checksum list
- secret exposure scan result
- fail on critical service missing/inactive
- fail on secret inline exposure
- warn on unknown non-critical units

### 3. Static Generated Artifact Guard

Detect:

- local `out/` missing public downloads
- local `out/` missing sidecar hashes
- local `out/` missing generated status/proof JSON that production currently serves
- production has generated artifacts not present in staged output
- sidecar hash mismatch
- destructive deploy would delete `receipt-static/**`, `project-status/**`, `node/*.json`, or public proof/status JSON

Planned command shape:

```bash
find out -type f | sort > /tmp/local-out-files.txt
ssh root@farpy.com 'find /opt/farpy.com/out -type f | sort' > /tmp/prod-out-files.txt
```

Output:

- preservation list to copy from production into staged deploy
- missing artifact list
- hash validation for downloads and sidecars
- fail if user-facing downloads or sidecars are absent
- warn if generated JSON will be regenerated by a known timer

### 4. `/etc/farpy` Drift

Detect:

- missing P0 env/key/config files
- unexpected new files under `/etc/farpy`
- P0/P1 permission drift
- group/world-readable secret-like files
- missing BTCPay/Stripe/web-render/auth/backup env boundaries

Planned command shape:

```bash
ssh root@farpy.com 'find /etc/farpy -type f -printf "%p\t%u:%g\t%m\t%s\n" | sort'
```

Output:

- current `/etc/farpy` metadata table
- diff against manifest paths
- fail on missing P0 files
- fail on secret-like files not `0600 root:root`
- warn on new files until classified

### 5. Local `out` vs Production Mismatch

Detect:

- local static build missing routes currently expected in production
- production-only generated data that would be deleted by clean deploy
- local download artifacts hash mismatch with manifest/release notes
- route shell mismatch for `/workspace`, `/receipt`, `/account`, `/topup`, `/downloads`, `/status`, `/addon`

Planned command shape:

```bash
test -f out/index.html
test -f out/downloads/index.html
test -f out/workspace.html -o -f out/workspace/index.html
```

Output:

- route shell presence matrix
- artifact mismatch matrix
- deploy allow/deny decision

## Verdict Policy

| Condition | Verdict | Deploy behavior |
| --- | --- | --- |
| Missing P0 route, critical service, P0 env file, or user-facing download | RED | Block deploy. |
| Secret-like file has unsafe permissions | RED | Block deploy until permissions fixed. |
| Static deploy would delete downloads/sidecars/receipt-static without preservation plan | RED | Block deploy. |
| Extra production route/service/file not classified | YELLOW | Require operator approval or manifest update. |
| Generated JSON missing locally but known timer can regenerate | YELLOW | Allow only with post-deploy regeneration check. |
| No failures, no unknown drift | GREEN | Allow deploy. |

## No-Secret Rule

The drift guard must never print env values, cookies, private keys, API keys, webhook secrets, OAuth credentials, Stripe secrets, BTCPay API keys, worker tokens, or NodeMuncher tokens.

Allowed:

- file path
- owner
- mode
- size
- checksum of public/static artifacts
- checksum of config files only when no secret content is printed
- whether an expected env variable name exists, redacted
