# FARPY_DAILY_FUNNEL_DASHBOARD_V1

Date: 2026-06-28

## Summary

Installed a lightweight hourly production funnel report that reads Caddy JSON access logs with `jq` and writes:

- `/opt/farpy/reports/funnel-latest.json`
- `/opt/farpy/reports/funnel-latest.txt`

The report is generated by:

- `/usr/local/bin/farpy-funnel-report`
- `farpy-funnel-report.service`
- `farpy-funnel-report.timer`

## Data Source

- Source log: `/var/log/farpy/access.log`
- Parser: `jq`
- Window: current UTC day, from `00:00:00Z` to generation time
- Runtime measured: `0.63s`

Note: at install time, `/var/log/farpy/access.log` last modified on `2026-06-12`, so the current-day report had zero counted requests. The report path and timer are healthy; counts will populate when Caddy writes fresh JSON access entries to the configured log.

## Internal Traffic Ignored

The report filters out routine/internal noise:

- `api.farpy.com /node/*` worker polling
- `/next`
- `/_next`
- `/worker-earnings`
- `/version`
- `/readyz`
- health probe paths
- static asset extensions

Public `farpy.com` web-render traffic remains countable unless it matches worker/health/static filters.

## Rollback

```bash
systemctl disable --now farpy-funnel-report.timer
rm -f /etc/systemd/system/farpy-funnel-report.service
rm -f /etc/systemd/system/farpy-funnel-report.timer
rm -f /usr/local/bin/farpy-funnel-report
systemctl daemon-reload
```

Generated reports can be removed with:

```bash
rm -f /opt/farpy/reports/funnel-latest.json /opt/farpy/reports/funnel-latest.txt
```
